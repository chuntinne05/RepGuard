# AppWorld v10: official simplified ReAct, Qwen3-Coder 30B, AppWorld 0.2

**Date:** 03/10/2026. **Final status:** six of six real train trajectories completed through Modal Ollama; runner exited 0; six of six scored by the official AppWorld 0.2 state-check in separate evaluator processes. Frozen protocol and runner were pushed to `dev` at `b232f98` **before** the first task call; the scorer was pushed at `2733e42`. This is a solver capability screen, not an ECRT, DART or HistRepEval method evaluation.

## Why this experiment was run

AppWorld 0.1.3 v8 found Qwen3-Coder 30B and Qwen3 32B each solved 3/6 on the **same** six tasks but had no one-model-only rescue. V9 GLM-4.7-Flash solved 0/6 on six different tasks. V10 changes to the official **current simplified ReAct** agent and matching AppWorld **0.2.0** data/evaluator on six more new train IDs. The version and tasks differ; v10 cannot be directly compared with v8/v9 as a scaffold or model effect. The question is whether this version-matched scaffold produces enough exact successes to justify a paired second model.

The setup used official AppWorld source commit `42b5bcf3cd334fee33f0c37c02070a9f5807add5`, package `0.2.0.dev0`, official 0.2.0 data, and the official simplified ReAct prompt/code. The official installation verification passed **147/147 train+dev tasks** with official solutions. This verification checks installation, not model accuracy. During agent execution, `load_ground_truth=False` and an initialization assertion prevented loading task gold. Task IDs were frozen from the ID-only SHA-256 one-per-generator train list (positions 25–30); no dev/test tasks or sealed holdout were used. The only changes to official agent code were Modal authorization/transport and gold isolation. Full configuration and hash `e46c3e85e8807ce2f0d479b2d9768d10a516481f5a396999667291c69b74975f` are in [`appworld_v10_simplified_protocol_2026-10-03.md`](appworld_v10_simplified_protocol_2026-10-03.md).

## Observed failure pattern and limits

Two failed tasks were close in check count (3/4 and 4/5); near-success still does not count as success. Another passed 5/8. This suggests that local partial progress is possible, but does not identify a general fix or prove that an extra verification prompt would have recovered the missing checks. One failed trajectory made **302 requests to one Venmo social-feed endpoint** within 18 model steps; the 40-step budget limits agent code executions, not every API request inside a code block. That shows an inefficient search/loop in that trajectory. Other task API-call counts were 96, 22, 53, 6 and 15, respectively; these are diagnostic environment requests and not equivalent to model calls. Exact causal attribution among prompt, model reasoning, task difficulty and scaffold needs controlled experiments on fresh tasks. No task instruction or protected gold is reproduced here.

The six-task sample was selected as a feasibility gate, not a representative benchmark estimate. A `1/6` screen cannot support an AppWorld population accuracy, a superior-method claim, or an A* submission on its own. In particular, comparing 1/6 on AppWorld 0.2 with 3/6 on v8 AppWorld 0.1.3 would confound task IDs, data version and scaffold.

## Predeclared decision and next work

The frozen gate required **at least 2/6 exact successes** before a paired Qwen3 32B run on these six IDs. V10 achieved **1/6**, so **do not run that paired control** and do not build a reputation/routing pool from this candidate. This decision was set before observing task outcomes. The v10 result does not prove Qwen3-Coder or simplified ReAct generally fails; it says this specific solver/version/budget has insufficient demonstrated success for the planned pool.

For the paper, preserve v1–v10 as transparent capability evidence, keep the MMLU-Pro 560-answer pool and HistRepEval decision-value work, and choose the next interactive setting by **verified solver success and two-way complementarity on fresh train tasks**. Before another large run, specify a different solver mechanism or environment and a cost-matched baseline; more same-family model swaps without a plausible source of rescue would add little information. The proposed active-audit/history method remains a hypothesis until it beats AuditOnly and a strong fallback with paired uncertainty at comparable cost on an untouched evaluation set. Do not open sealed holdout to tune around this negative pilot.
